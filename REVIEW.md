# pmix-rs Code Review

**Date:** 2026-10-13
**Scope:** Current `main` — `src/` (58,208 lines), `tests/` (201 files, 75,107 lines), `examples/` (19 programs)
**Edition:** Rust 2024, `rust-version = "1.85"`

---

## Executive Summary

This is a serious FFI binding crate for OpenPMIx. The public surface is a process-wide `PmixClient` (`Clone + Send + Sync`), free functions for data operations, and C-owned handles that stay `!Send` + `!Sync`. Error and data-type wrappers, the mock FFI harness, and the test tree are what make the crate usable without treating every call as raw `unsafe`.

This note describes the tree as it is. It does not track individual findings.

## Layout

Public modules declared from `src/lib.rs`:

`allocation`, `argv`, `cpu_locality`, `cbdata`, `data_ops`, `data_serialization`, `events`, `fabric`, `ffi`, `groups`, `info`, `monitoring`, `process_mgmt`, `query_log`, `security`, `server`, `threading`, `tool`, `utility`.

`mock_ffi` is compiled for tests and for the `mock_ffi` feature. `threading_assert` is test-only.

Core types still live in the crate root: `PmixError`, `PmixStatus`, the PMIx enum newtypes (`PmixDataType` and the rest), `Info` / `InfoBuilder`, `PmixOwnedValue`, `Proc`, and `PmixClient`. Supporting modules own the rest of the API.

Bindings are generated by `build.rs` into `OUT_DIR/bindings.rs` from the OpenPMIx headers the build is pointed at (`PMIX_PREFIX`, then include/lib dirs, pkg-config, then common prefixes). Nothing under `src/` is written at build time. The crate requires OpenPMIx ≥ 5.0; the full surface, including the progress-thread model, needs ≥ 6.1.

## What holds up

### Error and type wrappers

`PmixError` is a `#[repr(i32)]`, `#[non_exhaustive]` map of `pmix_status_t`, with `from_raw` / `to_raw` and success/error helpers. `PmixStatus` wraps a known `PmixError` or an unknown raw code so user-defined values are not dropped. The same `from_raw` / `to_raw` / `Unknown` pattern is used for the other PMIx enumerations (`PmixDataType` is `#[repr(u16)]`).

Public value tags go through `PmixDataType` rather than a bare `pmix_data_type_t`. Call sites that fill a C `pmix_value_t.type_` field convert with `to_raw()`.

### Session model

There is one client session type: `PmixClient`. It is the process-wide connect/disconnect handle. Drop does not call `PMIx_Finalize`; clones must not each finalize. Data ops (`put_value`, `get_value`, `commit`, `fence`, and the rest) stay free functions and take a `Proc` plus a per-call `Info`.

C-owned handles (`Info` and the other RAII wrappers around PMIx allocations) carry `PhantomData<*mut u8>` so they are `!Send` + `!Sync`. Rust-owned snapshots are what cross threads. Server upcalls and `_nb` completions run on the progress thread; `threading` provides `spawn_from_callback` and `CallbackChannel` for hopping off before blocking work. `THREADING.md` is the long form of that model.

`PmixServerModule` callback fields use the bindgen typedefs (`pmix_server_client_connected_fn_t` and the rest), not parameterless `extern "C" fn()` placeholders.

### Tests and examples

The test tree is larger than the library sources: 201 integration-test files plus unit tests inside `src/`. Daemon-backed tests are marked `#[ignore]` and run under the CI daemon / `prterun` jobs. `mock_ffi` covers the wrappers without a server. `ffi.rs` checks that bindgen saw a complete header set.

`examples/` has client, server, tool, fence, group, topology, and callback-hop programs, including `client_minimal.rs`, `server_minimal.rs`, and `tool_attach.rs`.

### Build

`build.rs` discovers headers and `libpmix` from the same prefix, refuses a header/library mismatch from the candidate-path search, and links with an rpath to that lib dir. Clippy in CI is `cargo clippy --lib -- -D warnings`.

## Verdict

The crate is a real OpenPMIx binding, not a stub inventory. The session model, the `!Send` handle rule, and the generated-bindings build are the contracts a caller has to follow. This file is a snapshot of that shape; it is not a punch list.
