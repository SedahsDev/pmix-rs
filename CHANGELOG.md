# Changelog

## Unreleased

- Fix (#520 review): every `PmixServerModule` C-ABI trampoline now has EXACTLY its bindgen `pmix_server_module_t` slot signature — argument order, argument types, cbfunc parameter types, and the `-> pmix_status_t` return — for both OpenPMIx 5.0.x and 6.1.x. `PmixServerModule::as_c_ptr` builds a typed `ffi::pmix_server_module_t` and assigns each slot with the trampoline as a typed function pointer, so rustc (not a transmute) verifies every signature at compile time; the untyped `fn()`-pointer transmute array is gone. Corrected upcalls include: `client_connected`/`client_finalized` now take `(proc, server_object, op_cbfunc, cbdata)` and return a status; `fence_nb` takes the participant `pmix_proc_t` array plus the modex blob `(data, ndata)`; `direct_modex` completes via `pmix_modex_cbfunc_t` (not `pmix_dmodex_response_fn_t`); `lookup`/`unpublish` take the C key list as borrowed `&[&str]` (pdata is a completion output); `connect`/`disconnect`/`group`/`job_control` take real `&[ProcView]` target arrays (never `NspaceView`); `register_events`/`deregister_events` take the status-code array; `listener` takes the listening socket plus the connection accept callback; `notify_event` matches the 5.x/6.x slot (no by-value `pmix_info_t` results argument); `tool_connected`/`tool_connected2` complete via `pmix_tool_connection_cbfunc_t`; `log`/`log2` take both the data and directives arrays; `allocate` takes the alloc directive; `monitor` takes the monitor info entry; `validate_credential` completes via `pmix_validation_cbfunc_t` and borrows the credential as `Option<&[u8]>`; `iof_pull` completes via `pmix_op_cbfunc_t`; `push_stdin` takes the target array, directives, and stdin blob; `session_control` takes the requestor proc plus `u32` session id; `resource_block` (6.x) takes the full 8-argument layout with a new `ResourceUnitView`. Status semantics: upcalls return `PMIX_SUCCESS` only when the host accepted the request (completing via the supplied callback), `PMIX_ERR_NOT_SUPPORTED` when the field is `None` (cbdata untouched), and complete the C cbfunc with `PMIX_ERROR` when the host callback panics, so clients are never left blocked on a garbage return. New completion wrappers: `ToolConnectionCallback` and `ValidationCallback`. All completion wrappers that hand slices back to C (`LookupCallback`, `InfoCallback`, `CredentialCallback`, `IofCallback`, `ValidationCallback`) map an empty slice to `(NULL, 0)` instead of a dangling `slice::as_ptr()`.
- Fix (#520 review): `Info::view(index)` now selects the requested element (`handle.add(index)` after the bounds check) instead of always returning entry 0, and returns `None` for a null handle. `AppView::argv`/`env` and `QueryView::keys` no longer claim `'static` — the borrowed strings are tied to the view's lifetime (valid for the duration of the upcall), stop at a missing NUL terminator, and `InfoView::as_str` returns `None` for a null PMIX_STRING pointer instead of invoking `CStr::from_ptr` on null.
- Breaking (#520, #541): The whole `PmixServerModule` callback surface now uses native callback views — no bindgen type appears in any public API item. This completes the #518 zero-leak campaign for the in-scope type list.
  - New borrowed, `#[repr(transparent)]` view types in `pmix::views` (`InfoView`, `ProcView`, `NspaceView`, `PdataView`, `AppView`, `QueryView`) with key/nspace/rank/typed-value accessors; raw C arrays convert to `&[View]` inside each C-ABI trampoline (null + 0 maps to an empty slice).
  - Breaking change to callback signatures: every `PmixServerModule` field is now a native Rust-ABI `unsafe fn` taking views (e.g. `publish: Option<ServerOpCallback<InfoView>>`, `spawn: Option<ServerSpawnCallback>`, `fence_nb: Option<ServerModexCallback>` over `&[ProcView]`/`&[InfoView]` plus the modex blob `(*mut c_char, usize)`), each matching the REAL bindgen slot argument layout (see the #520 review fix entry above). `#[cfg(pmix6)]` gating is unchanged. The `PmixServerModule { field: Some(cb), ..Default::default() }` idiom still compiles.
  - New one-shot completion-callback wrapper types following the `ModexCallback` / `OpCallbackWrapper` / `ReleaseCallback` pattern (`from_raw` + typed surface, one per distinct C signature): `DmodexResponseCallback`, `LookupCallback`, `SpawnCallback`, `ConnectionCallback`, `InfoCallback`, `CredentialCallback`, `IofCallback`, `ToolConnectionCallback`, `ValidationCallback` in `pmix::server::callbacks`. Raw `pmix_*_cbfunc_t` fn pointers no longer appear in public signatures.
  - `NotificationFn::on_notification` (events) now takes `results: &mut [InfoView]` instead of a raw `pmix_info_t` pointer + length.
  - Gated raw escape hatches to `pub(crate)`: `InfoList::get_info_iter`, `PmixAppObject::info_ptr`, `Info::as_ptr`, `Info::into_raw`. Native replacements: `Info::view(index)` borrows an entry as `InfoView`; `Info::empty()` builds the null directive array.
  - `utility::iof_pull` / `iof_pull_blocking` / `iof_deregister` / `iof_deregister_blocking` / `iof_push` / `iof_push_blocking` now take `directives: &Info` (pass `&Info::empty()` for none) instead of `&[pmix_info_t]`.
  - Known-remaining (out of scope, tracked separately): `pmix_value_t` sites in value_kinds.rs / value_ns.rs, `pmix_data_type_t` sites (data_ops, data_serialization, info.rs, utility, value_kinds, value_ns), `pmix_status_t` sites in client.rs / process_mgmt.rs / value_kinds.rs, and the enum-ish parameter sites (pmix_scope_t, pmix_rank_t, pmix_persistence_t, pmix_data_range_t, pmix_alloc_directive_t, pmix_iof_channel_t, pmix_info_directives_t, pmix_proc_state_t, pmix_value_cmp_t, pmix_proc_info_t, pmix_envar_t, timeval, uint).
- Breaking: Wrapped 10 data-plane/job callback fields (direct_modex, connect, disconnect, spawn, abort, log, log2, query, listener, monitor) with native Rust types in src/server/callbacks.rs. Raw callback types no longer appear in public signatures. Migration: use Native*Callback::new(your_fn) when constructing PmixServerModule.
- Breaking: Wrapped 10 server-module callback fields (allocate, job_control, session_control, resource_block, get_credential, validate_credential, iof_pull, push_stdin, group, fabric) with native Rust types. pmix_server_*_fn_t no longer appears in public signatures. Migration: use Native*Callback types from src/server/callbacks.rs.
- Breaking: Raw pointer accessors on PmixDataArray, PmixByteObject, and PmixDataBuffer are now pub(crate), removing public access to pmix_data_array_t, pmix_byte_object_t, and pmix_data_buffer_t. Migration: replace calls to these pointer accessors and direct FFI field access with the wrappers' safe typed accessors, such as len() and data().

- Breaking: Wrapped pmix_group_opt_t in GroupOption enum and pmix_group_operation_t in GroupOperation enum. group_join() and group_join_nb() now take GroupOption instead of pmix_group_opt_t. Migration: use GroupOption::Accept or GroupOption::Decline instead of raw FFI values. GroupOperation implements Display and as_str() for string conversion.
- Breaking: Wrapped 11 server module callback fields (client_connected, client_connected2, client_finalized, tool_connected, tool_connected2, publish, lookup, unpublish, register_events, deregister_events, notify_event) with native Rust types. pmix_server_*_fn_t no longer appears in public signatures. Migration: use Native*Callback types from src/server/callbacks.rs.
- Breaking: Wrapped pmix_resource_block_directive_t in ResourceBlockDirective enum. Functions resource_block_directive_string, resource_block, and resource_block_nb now take ResourceBlockDirective instead of raw u8. Migration: use ResourceBlockDirective::Standard, ResourceBlockDirective::Debug, etc.
- Breaking: Wrapped pmix_app_t access in PmixAppObject. as_mut_ptr() is now pub(crate); use typed accessors nprocs(), cmd(), argv(), env(), info() instead of direct struct field access.

- Breaking: Wrapped pmix_query_t in PmixQuery with typed builders. pmix_query_t no longer appears in public signatures. Migration: use PmixQuery::builder().keys(...).qualifiers(...).build() and PmixQueryConstructed::as_mut_ptr() for FFI calls.
- Breaking: Wrapped pmix_regattr_t in PmixRegattr with typed accessors. pmix_regattr_t no longer appears in public signatures. Migration: use PmixRegattr::name(), string(), type_(), description() instead of raw field access.
- Refactor: Split the 6,298-line `src/lib.rs` into focused modules (`error`, `enums`, `types_proc`, `value_kinds`, `client`, `value_ns`, plus the inline test module as `tests.rs`). `lib.rs` is now a 4KB crate root (docs, mod decls, macro, re-exports). No public API change; cross-module private fields became `pub(crate)`.
- Fix: Add InfoList RAII wrapper to prevent FFI memory leaks in PMIx Info list operations (#526)
- Fix: Wrap data serialization types (PmixDataBuffer, PmixByteObject) to prevent FFI type leakage (#543)
- Breaking: Wrapped fabric/device FFI types in native Rust wrappers (PmixCoord, PmixDeviceType, PmixResourceUnit, PmixCoordView, PmixDeviceDistance, PmixDevice, PmixEndpoint, PmixFabric, PmixGeometry, PmixTopology, PmixCpuset). Public API no longer exposes bindgen types. Migration: use `Type::from_raw()` and `type.to_raw()` for conversions.
- Breaking: Removed public exposure of `pmix_server_module_t` and related bindgen callback types from the pmix-rs crate. `PmixServerModule::as_c_ptr()` now returns `*const c_void` instead of `*mut pmix_server_module_t`. Migration: use an explicit `as *mut pmix_server_module_t` cast where the old return type was required, and uphold the unsafe FFI contract when using the result. See #550 and #518.
